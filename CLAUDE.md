## Working rules (from Akshay: follow exactly)

## Companion / avatar rules
- **Case-study pages have no avatar** (no `Companion`, `ScrollEffects` or shapes): they are reading pages, a fixed corner avatar would sit over diagrams and tables, and skipping it saves the GSAP and image weight. So they do not use `.section` / `.gutter` (no right gutter), `Footer` is rendered with `companion={false}`, and `Navbar` gets `home="/"` so its links go to `/#section`. The skip link lives in each page (home: "Skip to projects", case study: "Skip to content" -> `#main`), not in the root layout.
- One fixed avatar: large in the hero, scrubbed by GSAP into the bottom-right corner on scroll. Phones: avatar sits bottom-right in the hero (width 56vw, max 380) and is hidden after the hero.
- Pose follows the last section whose top passed 60% of the viewport: experience = typing, projects = think, demos = point, skills = music, about = pizza (its own pose, with the hobbies line), contact = wave. Under reduced motion the corner avatar stays on one static pose (typing), and phones hide it after the hero, so About also has an inline pizza image (`.about-pose` in `globals.css`, shown only on phones and under reduced motion, so only one avatar ever shows). Hero idles; no idle coffee, no click behaviour.
- Content must never sit under the corner avatar: `.section` / `.gutter` keep a right gutter. `prefers-reduced-motion` disables the scroll animation.
- Stacking project cards are sticky only at >= 1200px wide and >= 790px tall (last card scrolls normally); otherwise a plain list. Interactive targets are >= 44px (never below 24px).
- Layout must not shift: the SQL playground reserves its result height (CLS 0, including jumping straight to Contact).

## Avatar images, 404 page, hash links
- **Avatar pipeline** (no script, the originals are git-ignored): originals are 2400x1792 transparent PNGs in `assets/avatar-originals/`; published files in `public/avatar/` are WebP, `sharp(png).resize({ width: 600 }).webp({ quality: 82, effort: 6 })` for the desk poses (600x448, 26 to 32 KB) and width 1200 for the hero `avatar.webp` (1200x897). Every `<img>` needs `width` and `height`. Poses: typing, think, point, music, wave, pizza (About), plus `desk-pool.webp` (404 page only, not part of the Companion).
- **About hobbies line:** `about.hobbies` in `config/site.ts`, shown in About and indexed by the assistant as its own chunk ("About: outside work", `/#about`).
- **404:** `app/not-found.tsx` (copy in `site.notFound`): pool pose, heading "Scratch! This page isn't on the table", Home and Projects buttons, no corner avatar, `noindex`, canonical and Open Graph cleared. Next returns a real 404 status. **Its `<img>` must stay inside `<picture>`**: React adds a `<link rel="preload">` for every normal `<img>` it renders, Next includes the not-found tree in every page, so a bare image there made the home page preload the pool pose (WebKit warned). `<picture>` is skipped by that rule, so `fetchPriority="high"` on it is safe. Lighthouse on the 404 is audited in `qa/run.mjs` with `--ignore-status-code`, performance and accessibility only (SEO is below 100 by design for a noindex 404, and best-practices only allows the browser logging the 404 itself); mobile performance sits at about 95, the floor.
- **`components/HashScroll.tsx`** (rendered on the home page): links to `/#section` from case studies, the 404 and shared links used to land at the top about 9 times in 10 (ScrollTrigger's start-up refresh undid the browser's scroll to the hash). It re-applies the hash position for about 2.5 s and stops when the visitor scrolls or touches the page. `qa/checks/about404.mjs` tests landing with smooth scrolling left on; never force `scroll-behavior: auto` when testing links (that hid the bug before).

## Motion and polish (Phase 4b)
Everything below is off under `prefers-reduced-motion`; `qa/checks/motion.mjs` tests each effect and what it must not do.
- **Name reveal** (`FitLine` `reveal`, `.reveal-line` in `globals.css`): each headline line rises by `transform` only. **Never split the headline into letters and never put `clip-path` or `mask` on it**: measured on the production build, either one removes the headline from the Largest Contentful Paint candidates (even a clip that clips nothing), so the avatar image becomes the LCP (desktop lab LCP 0.24 s -> 0.98 s, performance 100 -> 99). A transform rise keeps the headline the LCP everywhere. Baseline to hold: mobile performance 100 / LCP 0.90 s, desktop 100 / 0.24 s. The fit constants in `Hero.tsx` are for the unsplit, kerned text.
- **Avatar tilt and parallax** (`Companion.tsx`): up to 8 degrees sideways and 5 up and down, plus a 10 px / 6 px drift the other way, only while the big hero avatar shows and only on fine pointers (off on touch).
- **Hero stream** (`HeroFlow.tsx`, `.hero-flow` CSS): nine lanes of dashes and dots, transform-only CSS animation, paused by an IntersectionObserver off screen and when the tab is hidden, at most 12% accent opacity (the dimmest hero text stays above 7:1; the check measures the brightest pixel). `HeroFlow` must stay the first positioned child of the hero, with the label and h1 `relative`, so it paints behind them (do not make the hero `isolate`: that would put the hero copy under the corner avatar).
- **Count-ups** (`CountUp.tsx`): every number in a stat counts up once when it scrolls into view and ends on the exact config string. The real text stays in the DOM (screen readers, no-JS, layout); an aria-hidden overlay is drawn while counting.
- **Card lift** (`.card-lift`): 4 px lift and accent glow on hover and on `:has(:focus-visible)`; under reduced motion only the static glow remains.
- **One accent system:** one purple and one orange (each with a deliberate light-theme twin). Always-dark surfaces use `text-ink-accent` / `bg-ink-warm` / `ink-*` tokens; the shape-shading tints are tokens too. `lib/palette.ts` mirrors the values for the Open Graph image, and `lib/palette.test.mts` (run by `npm run qa`) fails on any stray hex colour or raw accent `rgb()` in the source.

## QA (`npm run qa`)
One-time: `npm run qa:install` (installs `qa/` deps and Playwright WebKit; needs Google Chrome, or set `CHROME_PATH`). Then `npm run qa` builds into `.next-qa`, serves it on :3100 and runs everything: tsc, ESLint, npm audit, Lighthouse desktop + mobile on the home page and on every case-study page (performance must be >= 95), axe in both themes, CLS incl. jump-to-Contact, avatar overlap and poses, shapes vs text, stacking fit, nav at 129 widths, 24px targets, links, SEO/JSON-LD, content + Copy email, case-study pages (`casestudies.mjs`: head tags, OG image, sitemap, one h1 and the six sections, diagram, no avatar, back link, axe in both themes and on a phone, CLS, overflow, targets, links), About hobbies line, pizza pose and the 404 page (`about404.mjs`: real 404 status, noindex, no canonical, no pool-image preload on the home page, image size attributes, buttons, axe in both themes, CLS, phone and reduced motion, and hash links landing on their section), WebKit + CSP + DuckDB. Options: `-- --skip-build`, `-- --only=lighthouse,poses`. Raw output goes to `qa/out/` (git-ignored); exit code 1 on any failure. LinkedIn (HTTP 999) and sleeping Streamlit demos show as warnings, not failures. Checks read text in the page (e.g. the pitch and seeking line), so update `qa/checks/content9.mjs` when copy changes on purpose.
