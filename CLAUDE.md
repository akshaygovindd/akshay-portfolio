## Where things live

- **Case studies** (`/projects/[slug]`, one per project that has `caseStudy: "slug"` in `config/site.ts`; JobPulse has none yet). Text: `content/case-studies/<slug>.mdx`, always six `##` sections in this order: Problem, Architecture, Key decisions, Data quality and evaluation, Results, What I'd do next, then a `<Sources>` block mapping each number to a file in the repo. Page metadata (title, description under 160 chars, context line, diagram id): `caseStudies` in `config/site.ts`. Route and metadata: `app/projects/[slug]/page.tsx`; social card: `app/projects/[slug]/opengraph-image.tsx` (generated, palette colours, title in Anton from `assets/fonts/Anton-Regular.ttf`, SIL OFL licence next to it); sitemap entries come from `caseStudies` in `app/sitemap.ts`. Diagrams: `<Diagram id="pipeline" />` reuses `components/interactive/PipelineDiagram` (FoodLens); the others are static SVG from `config/diagrams.ts` drawn by `components/case-study/ArchDiagram.tsx` (theme colours via CSS variables, text description for screen readers). The case-study text follows the same rule as the rest of the site: every number is checked against the repo, none invented. Rules from a course brief are listed apart from my own decisions. A project card shows a "Read case study" link when `caseStudy` is set.
- **"Ask my portfolio" (RAG assistant, after Demos):** corpus = the four case-study MDX files (no `<Sources>` blocks), project + experience text in `config/site.ts`, and `public/resume.pdf` (contact line with phone/e-mail is dropped). `rag/` holds chunking (`chunk.ts`), corpus (`corpus.ts`), Neon pgvector (`db.ts`, `schema.sql`), retrieval (`retrieve.ts`: top-5 cosine + keyword fallback for exact terms), prompt and limits (`answer.ts`), rate limits (`ratelimit.ts`: 10/hour per HMAC-hashed IP and 200/day global, in the Neon `rate_limits` table; no question text stored). Route: `app/api/ask/route.ts` (AI SDK, gpt-5.4-mini, 500 output tokens). UI: `components/sections/Ask.tsx` + `components/interactive/AskLoader.tsx` (next/dynamic, error boundary) + `AskPanel.tsx`; chips and copy in `site.ask`. Neon project `portfolio-rag` (separate from the Instacart project). Env: `OPENAI_API_KEY`, `DATABASE_URL`, `RATE_LIMIT_SALT` (`.env.local` locally, Vercel production only). **Run `npm run rag:ingest` after ANY content change** (case-study MDX, `config/site.ts` project/experience text, `resume.pdf`): it re-embeds only changed chunks (hash), so reruns are cheap. `npm run rag:schema` applies the schema, `npm run rag:eval` (manual, calls OpenAI, about 4 cents; `-- --retrieval-only` is free-ish) reports hit@5 and citation rate from `eval/questions.jsonl`. QA check: `qa/checks/ask.mjs` (mocked API plus one live off-topic call).

## NEXT_PUBLIC_SITE_URL rule
Every absolute URL (canonical, Open Graph, Twitter, sitemap, robots, JSON-LD, manifest) must come from `NEXT_PUBLIC_SITE_URL` via `lib/site-url.ts` (value in `.env.production`). Never hardcode the domain, so a custom-domain switch changes that one value only.

## Companion / avatar rules
- **Case-study pages have no avatar** (no `Companion`, `ScrollEffects` or shapes): they are reading pages, a fixed corner avatar would sit over diagrams and tables, and skipping it saves the GSAP and image weight. So they do not use `.section` / `.gutter` (no right gutter), `Footer` is rendered with `companion={false}`, and `Navbar` gets `home="/"` so its links go to `/#section`. The skip link lives in each page (home: "Skip to projects", case study: "Skip to content" -> `#main`), not in the root layout.
- One fixed avatar: large in the hero, scrubbed by GSAP into the bottom-right corner on scroll. Phones: avatar sits bottom-right in the hero (width 56vw, max 380) and is hidden after the hero.
- Pose follows the last section whose top passed 60% of the viewport: experience = typing, projects = think, demos = point, skills = music, about = music (no pose of its own), contact = wave. Hero idles; no idle coffee, no click behaviour.
- Content must never sit under the corner avatar: `.section` / `.gutter` keep a right gutter. `prefers-reduced-motion` disables the scroll animation.
- Stacking project cards are sticky only at >= 1200px wide and >= 790px tall (last card scrolls normally); otherwise a plain list. Interactive targets are >= 44px (never below 24px).
- Layout must not shift: the SQL playground reserves its result height (CLS 0, including jumping straight to Contact).

## QA (`npm run qa`)
One-time: `npm run qa:install` (installs `qa/` deps and Playwright WebKit; needs Google Chrome, or set `CHROME_PATH`). Then `npm run qa` builds into `.next-qa`, serves it on :3100 and runs everything: tsc, ESLint, npm audit, Lighthouse desktop + mobile on the home page and on every case-study page (performance must be >= 95), axe in both themes, CLS incl. jump-to-Contact, avatar overlap and poses, shapes vs text, stacking fit, nav at 129 widths, 24px targets, links, SEO/JSON-LD, content + Copy email, case-study pages (`casestudies.mjs`: head tags, OG image, sitemap, one h1 and the six sections, diagram, no avatar, back link, axe in both themes and on a phone, CLS, overflow, targets, links), WebKit + CSP + DuckDB. Options: `-- --skip-build`, `-- --only=lighthouse,poses`. Raw output goes to `qa/out/` (git-ignored); exit code 1 on any failure. LinkedIn (HTTP 999) and sleeping Streamlit demos show as warnings, not failures. Checks read text in the page (e.g. the pitch and seeking line), so update `qa/checks/content9.mjs` when copy changes on purpose.
